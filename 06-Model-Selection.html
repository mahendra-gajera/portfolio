🎯 Which AI Model Should You Pick?

GPT, Claude, Gemini, Llama — practical guide with cost, speed & use-case fits · Simplified by Mahendra Gajera

💡 The Honest Answer

There is no "best" model. Only the right model for this specific job, with these specific constraints. A model that's overkill costs you 50x more for the same output. A model that's underpowered hallucinates and breaks your product.

This guide walks you through how I actually pick models in production — at Microsoft, for LSEG, and for client work. The framework: capability × speed × cost × privacy × tooling.

⚡ Rule of thumb I live by: Start with the cheapest model that might work. Measure with evals. Upgrade only when evals say you need to. Never pick by reputation alone.

📋 Real-World Use Cases PRACTICAL

Concrete production scenarios with model picks & reasoning. These are the patterns I see most often.

🤖 Customer support chatbot (high volume)
Claude Haiku 4.5GPT-4o-mini
10K+ conversations/day. Most queries are simple FAQ lookups. Latency matters (customers won't wait). Pick the cheap tier. Upgrade to Sonnet for hard cases via a router pattern.
📚 RAG over company knowledge base
Claude Sonnet 4.6GPT-4.1
Quality of answer matters. Retrieval handles the search; the model just needs to read context and write a grounded answer. Workhorse tier is the sweet spot. Don't waste Opus money here.
🧠 Multi-step agent (research, code, etc.)
Claude Opus 4.7Sonnet 4.6
Agents compound errors over multi-step loops. Each step needs to be right. Use Opus for planning, drop to Sonnet for sub-tasks. This is what I do for the SRE Agent at Microsoft.
💻 Code generation in an IDE
Claude Sonnet 4.6Opus for refactors
Sonnet is currently the strongest at code per dollar — Copilot, Cursor, and most coding assistants use it for a reason. Reach for Opus only for hard refactors or multi-file work.
📊 Structured data extraction (invoices, forms)
GPT-4o-miniClaude Haiku
Output schema is fixed (JSON). You don't need creativity, just accuracy. Cheap tier with structured output mode. Validate with Pydantic. Add eval gates.
📄 Summarize 500-page legal contracts
Gemini 2.5 ProSonnet (with chunking)
Gemini's 2M context lets you drop the whole doc in. Otherwise you need chunking + map-reduce summarization, which adds complexity.
🏥 Patient data analysis (regulated)
Llama 3.3 self-hosted
HIPAA, data residency, audit trails. Cloud LLMs are usually disqualified unless you have a BAA. Self-host on your own GPUs. Fine-tune on de-identified clinical data.
✍️ Marketing copy / creative writing
Claude OpusSonnet for drafts
Claude is widely considered the strongest at nuanced prose, voice matching, and creative work. Opus for hero copy, Sonnet for bulk drafting.
🎙 Voice / real-time conversation
GPT-4o RealtimeGemini Live
Native audio-in/audio-out, sub-300ms latency. Text-only models routed through TTS feel laggy and unnatural in voice apps.
📋 Classification at scale (10M+ items/day)

⚠️ Hidden costs nobody mentions:
• Caching — Anthropic/OpenAI both offer prompt caching at ~10% the cost. Use it for RAG.
• Batch APIs — 50% off for non-urgent work. OpenAI Batch & Anthropic Message Batches.
• Embeddings — separate cost from LLM. Easy to forget.
• Tool use — every tool call is another roundtrip = more tokens.
• Failed/retried calls — bugs and rate limits cost money too.

📐 Rules I Actually Follow PRODUCTION

What I learned the hard way, building production AI for Microsoft, LSEG, and others. Not theory — patterns that survived real incidents.

📏 Rule 1 — Start cheap, upgrade with evidence

Start with the cheap tier. Build evals. Run them. Only upgrade when evals say the cheap model is failing. I've watched teams burn $50K/month on Opus when Haiku would have hit their accuracy bar.

📏 Rule 2 — Use multiple models in one pipeline

Not all parts of a workflow need the same model. Router pattern: cheap model classifies the request, then routes to the right specialist. Used this at Microsoft to cut 60% of agent costs.
# Router pattern in production def route_request(query): intent = haiku.classify(query) # cheap classifier if intent == "simple_faq": return haiku.answer(query) elif intent == "complex_reasoning": return opus.answer(query) elif intent == "code": return sonnet.answer(query) else: return sonnet.answer(query) # safe default

📏 Rule 3 — Test with your actual data

Public benchmarks (MMLU, HumanEval) are not your use case. Build a golden dataset of 50–500 real queries from your product. Run all candidate models. Pick the cheapest that hits your quality bar.

📏 Rule 4 — Build for vendor independence

Wrap LLM calls in an abstraction (LangChain, LiteLLM, or your own). Swapping GPT-4 for Claude should be a one-line config change, not a refactor. Models deprecate; your code shouldn't break.
# Don't hardcode the vendor from langchain_core.language_models import BaseChatModel def get_llm(model_name: str) -> BaseChatModel: if model_name.startswith("gpt"): return ChatOpenAI(model=model_name) elif model_name.startswith("claude"): return ChatAnthropic(model=model_name) elif model_name.startswith("gemini"): return ChatGoogleGenerativeAI(model=model_name) # Now this works for any model: llm = get_llm(os.environ["MODEL_NAME"]) chain = prompt | llm | parser

📏 Rule 5 — Pick the model that matches your tooling

If your stack is Azure → GPT-4 via Azure OpenAI is the path of least resistance. AWS shop → Claude via Bedrock. GCP → Gemini via Vertex. The "best model" matters less than the "best model your platform supports without 3 months of procurement".

📏 Rule 6 — Watch for the "good enough" trap

Sometimes the cheap model is "almost as good." That gap might be 5% of test cases — but in production, 5% failure becomes thousands of bad responses per day. Match model strength to user tolerance for errors, not your eval averages.

📏 Rule 7 — Plan for model deprecation from day one

Every model gets deprecated eventually. Lock your version (gpt-4-1106-preview, not gpt-4). Re-run evals when you upgrade. Budget engineering time for migrations every 6–12 months.
⚠️ One last warning: Don't pick a model because of a benchmark you read on Twitter. Don't pick a model because your CEO read about it. Pick because your evals say it works for your task. That's the entire game.
